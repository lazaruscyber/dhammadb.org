## About

DhammaDB is an encyclopedia of the Theravāda Dhamma. Its articles follow the orthodox Theravāda position as found in the Pāli Tipiṭaka and its commentaries.

The site is completely static. There is no server, no database and no framework: every article is a Markdown file in the `pages` folder, and the whole wiki runs in the browser. You can open `index.html` straight from your computer, or host the folder anywhere that serves static files, such as GitHub Pages.

## Features

- **Markdown pages.** One `.md` file per article, with a short header for the title and categories.
- **Wiki markup.** Links between pages, categories, footnotes and references, infoboxes, navigation boxes, figures, galleries, callouts, hatnotes, quotations and more. See the formatting guide inside the wiki (`Help:Formatting`).
- **Built for reading.** A sticky table of contents that follows your place on the page, link previews on hover, sortable tables and a layout that works on phones.
- **Search.** Instant suggestions as you type, plus full-text search across every page. Press `/` to jump to the search box.
- **Special pages.** All pages, categories, recent changes, random page and "what links here".
- **Page IDs.** Every page shows a SHA-256 fingerprint of its source file. It changes whenever the page changes, so anyone can confirm a copy has not been altered.
- **AI transparency.** Articles that contain AI-generated content are labelled, and the label links to the site's [AI Policy](ai-policy.html).
- **Works offline.** Open `index.html` from disk with no internet connection and no local server.

## Getting started

1. Download or clone this repository.
2. Open `index.html` in any modern browser.

That's it. Everything else is optional.

## Project structure

```
.
├── index.html          The wiki
├── ai-policy.html      The AI Policy page
├── config.js           Site name, tagline, logo, main page and footer
├── build.command       Packs the pages into pages/_bundle.js
├── pages/              One Markdown file per page
│   └── _bundle.js      Generated by build.command (do not edit)
├── images/             Pictures used by pages
└── assets/             The wiki engine, styles and logo
```

## Writing pages

Each page is a Markdown file in `pages/` that starts with a header:

```markdown
---
title: Dukkha
categories: [Core teachings]
---

**Dukkha** ({{lang|Pāli|dukkha}}) is the first of the [[Four Noble Truths]].
```

| Header option | What it does |
|---|---|
| `title` | The page name that links point to. |
| `categories` | Lists the page in those categories. |
| `summary` | Short description used in search and link previews. |
| `image` | Picture used in search and link previews. |
| `redirect` | Sends readers to another page. |
| `toc` | `false` hides the table of contents. |
| `ai` | `false` removes the "Contains AI-generated content" label. |

The full syntax for infoboxes, references, navigation boxes and every other element is documented on the wiki's **Help:Formatting** page, with live examples.

### Building

Browsers do not let a page opened from disk read other files, so the Markdown files are packed into `pages/_bundle.js` before the wiki can show them.

After adding or changing pages, rebuild the bundle:

- **macOS:** double-click `build.command`.
- **Linux, or macOS Terminal:** run `bash build.command` in the project folder.

Then reload the wiki. The build also calculates each page's Page ID.

> [!IMPORTANT]
> `pages/_bundle.js` is what the published site actually reads. Maintainers should rebuild and commit it after merging page changes. Contributors do not need to include it in pull requests.

## Publishing

The repository is a ready-to-serve static website. To publish it with GitHub Pages:

1. Open the repository's **Settings** and choose **Pages**.
2. Under **Build and deployment**, set the source to **Deploy from a branch**.
3. Choose the `main` branch and the `/ (root)` folder, then save.

GitHub shows the site's address once the first deployment finishes. Any other static host works the same way: upload the whole folder.

## Contributing

To report a mistake without editing, follow the process on the wiki's **Help:Contribute** page, quoting the article's Page ID.

## Content policy

- Articles present the orthodox Theravāda position, grounded in the Pāli Tipiṭaka and its commentaries.
- Claims should be supported by references to sources that readers can check.
- The use of AI in writing articles is governed by the [AI Policy](ai-policy.html).
